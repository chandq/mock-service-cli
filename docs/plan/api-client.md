# 新增 API Client 接口调试工作台

## 1. 目标与首版范围

增加独立命令行模式，提供本地优先的 HTTP 接口工作台，覆盖“组织接口 → 配置环境 → 发送请求 → 检查响应 → 断言与批量执行”的完整流程。

已确认的产品选择：

- 独立启动，集合与环境配置保存为项目文件，便于 Git 管理。
- 支持 cURL、Postman Collection v2.1、OpenAPI 3.0/3.1 导入。
- 支持 Basic、Bearer、API Key、Cookie；OAuth Token 首版手动配置。
- 默认本机使用，显式开放局域网时要求密码认证。
- 首版不包含 JavaScript 脚本、WebSocket、SSE、gRPC、云同步和多人协作。

功能组织参考 [Bruno 集合执行](https://docs.usebruno.com/get-started/bruno-basics/run-a-collection)和 [Postman Collection 模型](https://github.com/postmanlabs/postman-collection)，只承诺下述明确支持的能力。

## 2. CLI、架构与数据保存

### CLI 接口

```bash
# 默认使用当前目录下的 .mock-service-client 工作区
mock-service-cli --api-client --open

# 指定工作区及端口
mock-service-cli --api-client ./api-tests --port 8090

# 允许白名单内的局域网设备访问
mock-service-cli --api-client ./api-tests --host ./allowlist.txt --auth 'password'
```

- 新增 `--api-client [directory]`，默认关闭；页面位于独立服务的 `/`。
- 复用 `--port`、`--open`、`--silent`、`--host`；默认端口 8090，新模式的 `--port 0` 使用系统分配端口。
- 扩展 `--auth`，允许用于文件浏览器或 API Client；API Client 使用 `--host` 时必须同时指定密码。
- 与 Mock、静态服务、文件浏览器、Socket 和现有代理模式参数互斥；冲突时给出明确错误。
- 工作区首次保存时初始化。启用此模式即允许保存其配置，不依赖文件浏览器的 `--edit`。

### 模块与构建

- 在 `src/lib/apiClient/` 内分离服务入口、请求执行、工作区存储、导入转换、断言和浏览器资源。
- 服务端保持 CommonJS、JavaScript、Express；前端使用原生 JavaScript 模块和静态 HTML/CSS，不引入应用框架。
- 浏览器编辑器采用按需加载的 CodeMirror 6；Cookie 使用 `tough-cookie`，YAML 使用 `yaml`，选择兼容 Node 18 的版本。
- 接入现有 CLI 子进程、runtime 懒加载和 esbuild 构建，补齐 Windows Ctrl+C、取消请求、临时文件清理和端口释放。
- 更新 npm 资源清单和打包验证；light、ultra 均包含相同工作台功能，未启用时不初始化新服务。

### 数据与内部接口

- 工作区包含版本化元数据、每集合一个 JSON 文件、每环境一个 JSON 文件；使用稳定 ID、固定格式和相对引用，避免无意义 Git diff。
- 请求模型包含方法、URL、参数、请求头、Body、认证、设置、断言及变量提取规则；参数和请求头使用有序列表，保留重复项。
- 异步读写；保存采用临时文件与原子替换。通过版本校验发现外部修改和多标签页冲突，返回 `409`，禁止静默覆盖。
- API 只接受资源 ID，不接受任意磁盘路径；校验目录边界、符号链接和文件大小。
- 历史、标签页和布局保存在 IndexedDB，按工作区隔离；历史默认最多 500 条，不保存响应正文和解析后的密钥。
- Secret 变量、认证凭据及 Cookie 默认只存当前会话内存；项目文件保存变量引用，刷新或重启后重新填写。

内部 API 统一位于 `/__api-client/api/`，提供配置、会话、集合、环境、上传、导入预览、执行与结果下载。执行返回 `202 + executionId`，通过查询获取进度和结果，通过取消接口中止；上游 HTTP 状态与工具自身错误分开表示。

## 3. HTTP 调试与测试能力

### 请求与响应

- 支持 GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。
- URL 与 Query 参数双向编辑，支持参数启停、重复键、路径变量及编码预览。
- Body 支持无正文、JSON、文本/XML、URL 编码表单、multipart 文件上传和二进制文件；文件由浏览器选择，不接受远程指定服务器本地路径。
- 支持认证配置继承；显式请求头与自动认证头冲突时提示修正，避免隐式覆盖。
- 环境变量采用 `{{name}}`，优先级为运行时提取值 → 环境 → 集合；未定义变量阻止发送并定位。
- Cookie 提供查看、编辑、清除及自动携带开关，按会话和工作区隔离；不使用浏览器自身登录 Cookie。

请求通过 Node `http/https` 执行，统一处理连接复用、超时、取消、TLS、Cookie 和重定向，避免目标接口 CORS 限制。

- 默认超时 30 秒，可调整至 1–300 秒；默认验证 TLS，允许在单个请求中显式关闭并显示状态。
- 自动跟随重定向最多 10 次，遵循方法转换规则；跨源跳转剥离凭据，不自动重试请求。
- 响应展示状态、耗时、大小、最终 URL、重定向链、请求实发信息、响应头和 Cookie。
- 正文提供 JSON 树、格式化、原文、搜索、复制及下载；HTML/XML 作为文本，不执行响应中的内容。

### 集合、断言与批量执行

- 集合与文件夹支持新建、复制、重命名、移动、排序、删除和搜索。
- 支持状态码、响应头、耗时及 JSON Pointer 对应字段的存在性、类型、相等和包含断言。
- 支持从响应头或 JSON Pointer 提取变量，供后续请求使用；提取值默认仅本轮运行有效。
- 集合执行按顺序运行，支持请求选择、迭代次数、间隔、失败后继续或停止、主动取消及 JSON 报告导出。
- 批量运行使用独立变量上下文和 Cookie 副本，避免污染手动调试会话；不作为压力测试工具。

### 导入导出

- cURL：支持常见方法、URL、请求头、认证及 Body 参数；仅解析文本，绝不执行命令或 shell 展开；文件引用提示重新选择。
- Postman v2.1：导入集合、目录、请求、变量及支持的认证；脚本、动态变量和未支持配置列入兼容性报告。
- OpenAPI 3.0/3.1：支持 JSON/YAML，按标签组织接口，根据参数、示例、Body 和认证定义生成请求；首版只解析文档内部 `$ref`。
- 导入先预览数量、错误及兼容性，再确认写入新集合；不覆盖已有数据，不静默丢弃不支持内容。
- 导出支持原生版本化 JSON 和单请求 cURL；默认保留变量引用，隐藏敏感值。

## 4. 界面、性能与访问边界

### 界面与交互

采用适合开发工具的三栏布局：左侧集合/历史，中部请求编辑，右侧响应；窄屏切换为上下或单面板布局。

- 默认中文界面，浅色/深色/跟随系统主题；中性色背景、清晰层级和统一状态色。
- 多请求标签页、可拖动分隔栏、环境切换、未保存标识及关闭确认。
- `Ctrl/Cmd+Enter` 发送，`Ctrl/Cmd+S` 保存，`Ctrl/Cmd+K` 搜索。
- 参数表格支持键盘导航、批量粘贴和启停；错误定位到具体字段。
- 明确区分空白、加载、成功、网络失败、断言失败、超时和取消状态。
- 请求发送、集合保存、导入与批量执行均有反馈；保证焦点可见及键盘可操作。

### 性能策略与验收目标

- 首屏只加载工作台基础资源；编辑器及复杂响应处理按需加载，运行时不依赖 CDN。
- 大集合使用虚拟列表；JSON 解析、格式化和搜索放入 Web Worker，响应树按节点展开。
- 默认正文预览上限 1 MiB，超过后提示下载；请求及上传上限 100 MiB，响应传输及解压后均限制为 50 MiB。
- 每会话最多 4 个在途请求，服务全局最多 16 个，等待队列上限 100；超限明确反馈。
- 大响应流式写入临时文件，设置总容量上限与过期清理，取消和退出时释放资源。

在固定测试机器、记录 Node/浏览器版本的条件下验收：

- 首屏基础 JS/CSS gzip 合计不超过 250 KiB，编辑器独立计量。
- 本机服务就绪后，页面可交互时间不超过 1 秒。
- 1,000 条请求集合中，搜索和切换操作 P95 不超过 100 毫秒。
- 处理 10 MiB JSON 时，主线程无超过 200 毫秒的长任务，取消操作仍可响应。
- 连续执行 100 次请求并清理后，无持续增长的连接、临时文件或结果缓存。

### 访问边界

- 默认仅监听 localhost；局域网访问沿用现有 IP/CIDR 白名单，并保护页面、API 和结果下载。
- 对 Host、Origin 和会话令牌进行校验，不向任意网页开放执行 API，防止跨站调用及 DNS rebinding。
- 目标 URL 仅接受 HTTP/HTTPS；允许本地和内网接口调试，每次重定向重新校验目标。
- 工作台认证信息不转发给目标服务；日志不包含密码、Token、请求正文和完整敏感 URL。
- 上传和下载使用不可猜测的临时 ID，并校验会话归属；前端安全渲染所有导入内容和响应内容。

## 5. 实施顺序与验证

按以下顺序交付，每阶段均需具备可运行页面和对应测试：

1. **基础闭环**：CLI、独立服务、工作区、访问控制、基础请求发送与响应展示。
2. **日常调试**：现代化布局、编辑器、集合、环境、认证、Cookie、历史和文件上传。
3. **迁移与测试**：导入导出、声明式断言、变量提取、集合执行及结果报告。
4. **性能与集成**：虚拟列表、Worker、大响应处理、跨平台退出、双版本打包及文档。

测试与完成标准：

- Tap 覆盖模型、变量替换、导入转换、断言、保存冲突、路径边界和资源限制。
- 使用本地 HTTP/HTTPS 测试服务器验证重复参数、请求/响应头、上传、压缩、Cookie、跨源重定向、TLS 失败、超时及取消。
- 安全测试覆盖跨站请求、非法 Host、未认证访问、会话越权、恶意导入、符号链接逃逸及响应 XSS。
- 增加 Playwright 开发测试，覆盖创建并保存请求、切换环境、发送与取消、导入预览、集合执行、刷新恢复、主题及快捷键。
- 验证源码入口、构建入口与 light/ultra 包；在 Windows、Linux、macOS 检查启动、路径、浏览器打开和进程退出。
- 执行相关 Tap 测试、`npm run lint`、`npm test`、`npm run test:src` 和准备本地双版本产物后的 `npm run verify:packages`。
- 更新 README、CLI 帮助及工作台使用文档，说明文件格式、凭据保存、导入兼容性、限制和局域网访问方式。
- 最终仅保留有意的源码、测试、构建配置和文档变更，不提交生成产物，不执行发布。
